# Codex Memory：國考筆記蒸餾協作者

## 啟動規則

- 任何 TWMD_EXAM 工作前，先讀 `docs/agent_memory_and_skill.md` 與 `_agent_memory/` 內相關 agent 檔案；不要只依賴外部長期 memory 搜尋。
- 在本專案中，`_agent_memory` 是工作流程與指令別名的真相來源；`01_notes` / `03_focused_topics` 是內容權重來源。

## 使用者模型

使用者不是要建立完整醫學百科，而是在準備台灣醫師國考二階。核心任務是用可吸收的知識量，覆蓋國考常考判斷點，讓作答時的思緒權重更接近正確方向。

可以把互動視為 teacher-student distillation：

- teacher：考題、標準答案、主流教科書/指引中的穩定考點。
- student：使用者自己的筆記系統與記憶容量。
- distillation 目標：把龐大醫學知識壓縮成「能解題、能避免混淆、能導正直覺」的精簡筆記。

## 權重來源

優先讀取與修改：

1. `01_notes`：使用者主筆記，是長期記憶與複習入口。
2. `03_focused_topics`：考題解析與筆記對應，是判斷重要性與缺口的主要證據。

輔助來源：

- `01_notes/精華筆記`：放跨科易混、唯一例外、相反規則、常被選項反殺的精華整理。
- `02_past_exams`：原始考題資料。
- `04_daily_review`：複習輸出。

## `04_daily_review` 開發方法

`04_daily_review` 最有價值的產物是每次考古、每科一份的「補充知識草稿」，例如 `04_daily_review/114_1/2026-06-01_114_1_醫學五_補充知識草稿.md`。這類檔案用來讓使用者快速吸收「該年度考古暴露出、但 `01_notes` 沒有或不足」的知識，先作為審核稿，不直接併入正式筆記。

產生方式：

- 讀取 `02_past_exams/parsed/<exam_session>/<exam_session>_醫學X.json` 或 `.md`、`03_focused_topics/<exam_session>/<exam_session>_醫學X_逐題解析.json` 或 `.md`、以及對應的 `01_notes/醫學X/note_X.md`。
- 參考既有高品質草稿格式，尤其 `114_1_醫學五_補充知識草稿.md` 這種「可直接吸收/可併入筆記」格式。
- 系統性比對題目、答案、逐題解析與 note 現有內容；輸出「實際可補進筆記的知識內容」，不要只列缺口、覆蓋率、note 原文摘錄或巨大分析表。
- 優先保留高考頻、可泛化、會影響作答的內容：分類定位、鑑別方向、處置門檻、禁忌、用藥選擇、篩檢策略、常見錯誤直覺。
- 過濾太細、低機率、純記憶史實、查表細節、單一冷門基因/比例/新藥副作用、附圖才成立、答案標成 `#` 或答案不穩的題目；必要時放最後「候選補充：可先看，不一定併入正式筆記」。
- 格式用繁體中文、短句 bullet、考試導向；依科別/主題分段；每段加 `建議補到：` 指向未來應併入的 `# > ##` 位置。
- 專有名詞第一次出現要附英文/full name 與中文，例如 `CVID（common variable immunodeficiency，常見變異型免疫缺乏）`。
- 預設只建立或更新 `04_daily_review/<exam_session>/<date>_<exam_session>_醫學X_補充知識草稿.md`；除非使用者明確要求，不再產生舊式 `note缺口分析`、`note缺口確認` md/json。
- 做 04 草稿時不要直接修改 `01_notes`；等使用者審核或要求「補進筆記」時，再把精簡內容併入正式筆記。

## 筆記優化原則

- 以國考解題價值為核心，不為單題擴寫過多背景。
- 優先補「分類定位、鑑別方向、處置門檻、唯一例外、時間/數值 cutoff、容易反著想的點」。
- 保持使用者筆記風格：繁體中文＋英文關鍵詞，短句、括號、箭頭、表格少量使用。
- `Z9`：章節級 multi-agent 筆記結構整理流程；這是無語意代號，不能用字面意思推測任務。若使用者只給專科名，例如 `Z9 肝膽腸胃科`，先解析成 `01_notes` 裡對應的 top-level `# 肝膽腸胃科`。
- `Z9` 必須真的使用 multi-agent / subagent 分工；若當前環境沒有可用 multi-agent 工具，要停下回報 blocked，不能單 agent 自己改完整章後宣稱完成。每個 worker 只負責一個 top-level `#` 或 main agent 明確切出的互斥 `##` 範圍；main agent 監督是否徹底落實結構整理、同步 nested mirror、回報實際 touched `# / ##`。
- `Z9` 的整理規格：把難讀的平鋪長句改成巢狀 bullet。當 `Exam：`、`Tx：`、`Dx：`、`Risk：`、`C/I：`、`Pitfall：` 是父層時，細節要縮排在下面；主詞/項目放前面，再用 `for`、`if`、`since`、`because` 表示用途、條件或原因。避免把多個檢查/治療塞在同一層，例如 `Exercise ECG... Stress imaging... SPECT...` 要收進 `Exam：` 底下。
- 舊名「任務一 / 任務二 / 章蜂巢」全部禁用，不再作為 durable workflow 名稱，因為既有 memory 中 `Task 1` / `Task 2` 已有多個舊意義，且功能性名稱會誘發 agent 單靠字面腦補流程；`Z9` 不是 `03_focused_topics` 生成、轉換或修復。
- 筆記文法慣例：常用「主題：內容」開頭；用「；」分隔同層內容；`Tx`、`Exam`、`SS`、`RF` 等分類標籤一律用英文縮寫；補充說明用中文括號「（）」。
- 新增英文術語或縮寫時，除 `Tx`、`Exam`、`SS`、`RF` 等既有分類標籤外，第一次出現要加中文或 full name；太難或不直覺的英文（如 incision 類型、dehiscence、procedure 名稱）不可只放英文，也不要自行發明未解釋縮寫。
- 病名/症候群的英文縮寫第一次出現時要寫出 full name（可搭配中文）；基因、蛋白、突變/變異編碼如 `APC`、`WT1`、`STK11`、`VHL/HIF` 不用硬展開，除非該展開本身是考點。
- 醫療參數/量表/分級/criteria/cutoff：不要只為單題記孤立數值或單一級別；先判斷其性質（篩檢、診斷、嚴重度、處置門檻、預後、追蹤），用最短篇幅建立完整分類骨架與決策意義，再附1個高頻應用例。若完整 scale 很長，只保留考試會改變處置的節點。
- 冷門模型/量表/人名縮寫：不要只放縮寫；至少寫出 full name、用途或考試差異點（例如「某縮寫是預後分層模型」「LDH屬另一模型」），避免使用者複習時還要重查。
- 解剖/機轉補筆記：避免用「陷阱」清單堆孤立事實；優先改寫成地圖/路徑/來源/支配/相鄰關係，讓錯誤選項可由結構推出。只有真正跨題常混淆時才放易混淆筆記。
- 圖片/圖譜格式：新增多張同主題圖譜時，優先放在相關段落下方，用 Markdown 表格每排三張並排；使用原圖檔與相對路徑（如 `../assets/...`），不要用低解析縮圖，也不要用 HTML `<img>` 控制大小。單張圖可維持一般 Markdown 圖片；若加入 assets，外層 `01_notes/assets` 與 `twmd-exam-notes/01_notes/assets` 需同步。
- 不大改既有段落，只針對錯誤、混淆、缺口做局部修補。
- 若新增或修改內容，回報所在檔案、`#` 大章、`##` 小節與行號；回答「補在哪」時一定要明講 `##` 位置，方便使用者索引。
- 若內容適合跨科比較，放入 `01_notes/精華筆記/易混淆詞整理.md`；若是單科知識，放回該專科主筆記。

## 回答風格

- 使用者問一段筆記是什麼意思時，簡短解釋，不展開成教科書。
- 使用者要求補筆記時，直接找位置並編輯；完成後說明補到哪個 `##`，不要只給檔案行號。
- 使用者表達「這會不會太細」時，要幫忙做考試權重判斷：大考點、可精簡記、可跳過。
- 使用者常需要的是「為什麼我會選錯」與「下次怎麼分」，回答要導正判斷框架。

## 工程注意

- 主要可編輯工作區在外層資料夾；若相同檔案也存在 `twmd-exam-notes` nested repo，修改後需同步。
- 不要自行 push/commit，除非使用者明確要求。
- 使用者要求「推到 GitHub」時，預設直接推到 `main`，不要建立雲端 branch 或 draft PR；除非使用者明確要求 PR/branch。若必須暫用本機 branch，名稱不要帶 `codex`。
