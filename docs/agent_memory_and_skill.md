# Agent Memory / Skill 使用指南

## 專案目標

本專案的筆記維護不是完整醫學知識庫，而是「國考導向的知識蒸餾」。使用者會用有限可吸收的知識量覆蓋醫師國考二階，因此 agent 的任務是把考題、解析與主筆記壓縮成可作答的判斷框架。

## Teacher-Student Distillation 工作模型

- Teacher：歷屆考題、標準答案、穩定醫學知識、臨床 guideline 中國考會考的部分。
- Student：使用者目前的 `01_notes` 與記憶負荷。
- Distillation output：精簡筆記、易混淆對照、方向修正、選項判斷權重。

每次使用者要求「補一下」、「我不懂」、「這題要不要記」時，都視為一次蒸餾迭代。

## 權重優先順序

1. `01_notes`：主筆記，最優先維護。
2. `03_focused_topics`：考題解析與筆記對應，用來判斷哪些章節常考與筆記缺口。
3. `01_notes/Codex精華筆記`：放跨科易混、相反規則、唯一例外、藥物比較、同名詞混淆。
4. `02_past_exams` / `04_daily_review`：必要時輔助查題與複習輸出。

## 何時用 Skill / Memory

- Memory：記住使用者偏好、筆記風格、常見錯誤類型、專案權重。不要把單一醫學事實塞成長期偏好，除非它影響協作方式。
- Skill：當任務需要固定流程時使用，例如 GitHub push、文件生成、批次稽核、或專門工具流程。醫學筆記優化本身以本文件與 `_agent_memory/codex.md` 為主要行為準則。

## 筆記修改規則

- 先找現有 `#` / `##` 位置，能補原段落就補原段落。
- 新增內容要短，優先寫能分辨選項的規則：
  - 「A 是最常見，但 B 是最危急」
  - 「此數值可追蹤，但不代表嚴重度」
  - 「此藥孕婦唯一可用/禁用」
  - 「這個 sign 同名但不同系統」
- 不為單題擴張過度；如果太細，回覆「可跳過」或放入易混淆筆記而非主筆記。
- 若修正錯誤，避免重寫整段，保留使用者原本精簡風格。

## 回報格式

完成筆記修改後，回報：

- 檔案路徑與行號。
- 所屬 `#` 大章與 `##` 小節。
- 實際補了什麼判斷點。
- 是否同步到 `twmd-exam-notes` nested repo。

## 常見輸出型態

- 單題觀念釐清：直接用 3-6 行說明。
- 筆記補強：改檔後回報位置。
- 易混淆整理：加入 `01_notes/Codex精華筆記/易混淆詞整理.md`。
- 系統性稽核：先列稽核 md，使用者確認後再改主筆記。
